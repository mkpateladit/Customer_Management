# Customer Management (CRUD) — Distributor Portal

Django + MySQL module for managing customer/retailer records.

- **Distributor**: add, view, update, delete, and search their own customers.
- **Admin / Super Admin**: view and manage customer records across **all** distributors.

## Tech stack
HTML, CSS, JS (Bootstrap 5 via CDN), Python, Django, MySQL.

## 1. Install dependencies

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

> `mysqlclient` needs MySQL's C build tools available on your system
> (e.g. `sudo apt install default-libmysqlclient-dev build-essential` on
> Ubuntu, or `brew install mysql-client` on macOS). If you can't install
> it, `mysql-connector-python` (also in requirements.txt) can be used
> instead — just change `ENGINE` in `settings.py` to
> `'django.db.backends.mysql'` with `mysqlclient`, or swap to a
> connector-based backend if you prefer.

## 2. Configure the database connection

The project reads DB credentials from environment variables (see
`customer_project/settings.py`). Defaults assume a local MySQL server
with a `root` user and no password:

| Variable      | Default                  |
|---------------|---------------------------|
| `DB_NAME`     | `customer_management_db` |
| `DB_USER`     | `root`                   |
| `DB_PASSWORD` | *(empty)*                |
| `DB_HOST`     | `localhost`               |
| `DB_PORT`     | `3306`                    |

Set them before running any `manage.py` command if your setup differs, e.g.:

```bash
export DB_USER=root
export DB_PASSWORD=yourpassword
```

## 3. Create the database

Two options — pick one:

**Option A — Python script (recommended):**
```bash
python database/create_database.py
```

**Option B — raw SQL:**
```bash
mysql -u root -p < database/schema.sql
```
(`schema.sql` also documents the full table structure for reference,
including the tables Django's migrations create automatically.)

## 4. Create the tables (Django migrations)

```bash
python manage.py migrate
```

This creates `auth_user`, `profiles`, `customers`, and Django's other
built-in tables (sessions, admin log, etc.) inside the database you just
created.

## 5. Create an Admin / Super Admin account

```bash
python manage.py createsuperuser
python manage.py set_admin <username>
```

`set_admin` sets that user's Profile role to `admin`, giving them
visibility into every distributor's customers. Anyone who registers
through the app's **Register** page automatically becomes a
**Distributor** and only ever sees their own customers.

## 6. Run the app

```bash
python manage.py runserver
```

Visit:
- `http://127.0.0.1:8000/` — redirects to the customer list (login required)
- `http://127.0.0.1:8000/customers/register/` — distributor sign-up
- `http://127.0.0.1:8000/customers/login/` — login
- `http://127.0.0.1:8000/admin/` — Django admin (for the superuser)

## Features implemented

- **Create**: `Add Customer` form with server-side + client-side validation
  (name length/characters, phone format, pincode format, email format).
- **Read**: paginated customer list + detail page.
- **Update**: same form as create, pre-filled.
- **Delete**: confirmation page before deletion.
- **Search**: filters by name, email, phone, company, city, or GST number
  (`?q=`), plus an active/inactive status filter.
- **Role-based access**: Distributors only ever see/edit/delete their own
  customers (enforced in `views.py`, not just hidden in the UI); Admins see
  and manage everything.
- **Routing**: all CRUD + search routes live in `customers/urls.py`,
  namespaced as `customers:...`.

```
├── manage.py
├── customer_project/        # settings, urls, wsgi/asgi
├── customers/                # models, forms, views, urls, admin
│   ├── migrations/0001_initial.py   # generated by Django (makemigrations)
│   ├── management/commands/set_admin.py
│   ├── static/customers/{css,js}
│   └── templates/customers/*.html
├── database/
│   ├── create_database.py    # creates the empty MySQL database
│   └── schema.sql             # raw SQL reference for the schema
├── static/                   # global static (placeholder)
├── media/                    # uploads (placeholder)
└── requirements.txt
```
